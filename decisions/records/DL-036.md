## Context

When the player builds the sync map itself, it has read each SVG page's `viewBox`, and gives each page its aspect ratio before the images arrive, so the layout doesn't jump (DL-014). With a prebuilt map (`sync`, the attribute or the property, DL-017), it reads no SVGs and has no sizes: `loadSync` returns no page sizes, and the pages collapse until their images load. `segno build-sync` (DL-035) makes prebuilt maps the expected path for sites with a build step, so this gap would hit them all. The format is to be frozen at 1.0, so a missing field is cheapest to add now.

## Decision

Sync map version 1 gains an optional field:

```json
{ "v": 1, "pages": [[2976, 4209], [2976, 4209]], "bars": [], "events": [] }
```

- `pages`: one `[w, h]` per page, in page order, as read from each SVG's `viewBox`, in its own units. Only the ratio of `w` to `h` is meaningful, and readers must not assume a unit.
- `buildSync` always writes `pages`, since it is given the sizes. Maps without it (older maps, other producers) stay valid, and `v` stays `1`: older readers ignore the field, which DL-003's versioning allows.
- `checkSyncMap` checks `pages` when present: an array of `[w, h]` with positive finite numbers, and every bar and note on a page within it.
- The player takes each page's aspect ratio from the map's `pages`, for the `sync` attribute, the `sync` property and maps it builds itself alike: `loadSync` no longer returns page sizes of its own. The core names the tuple `Page`. If the map's number of pages differs from the number of pages the player was given, the map doesn't belong to these pages: it is rejected like any other mismatch, and the player plays without markers and warns (DL-017).
- `docs/sync-map.md` documents the field.

## Rationale

- The sizes cost a few bytes per page and remove a layout jump on every prebuilt map.
- `[w, h]` tuples follow the format's existing style (DL-003).
- Keeping the raw `viewBox` numbers means no rounding decisions. Only the ratio matters to a player.
- A page-count mismatch is a stronger signal than the existing check (positions on a page that wasn't given). It catches a map built for another export of the same score, which would otherwise draw markers on the wrong pages.

## Consequences

- Every map `buildSync` produces changes shape (one more field), so tests and fixtures that compare whole maps are updated. The core's size budget absorbs the few added lines.
- A producer that omits `pages` gets the old behaviour, with the layout settling as the images load.
- The canvas views (DL-023) keep getting their sizes as they do today; whether they use `pages` is left to a later change.
