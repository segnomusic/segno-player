## Context

Segno OMR, a hosted transcription service, shows its scores in `<segno-player>`. Its listeners need tempos from 20% to 200%, because a transcription's tempo is sometimes wrong and can't always be guessed. Time-stretching the MP3 smears sustained and vocal sound below about 85% in every browser (the roadmap's open item on tempo says the same). The host will instead play MuseScore's own MIDI of the score through a SoundFont synthesizer in the page. That synthesizer changes tempo by starting notes earlier or later, so slow playback sounds clean. Its note-ons fall within 0.2 ms of the sync map's times, repeats and fermatas included, so the sync map is unchanged.

DL-001 keeps Segno free of rendering and synthesis, and the roadmap's option of a synthesizer inside Segno would need an amendment to it, an engine abstraction and a lazy-loaded entry to respect the size budget (DL-011). The player only uses a small part of `HTMLMediaElement` (DL-005), and a host can implement that part over any engine.

## Decision

The player accepts an external media object. It never contains a synthesizer itself.

- **`SegnoMedia`**, an exported type: what the player needs from its audio, a subset of `HTMLMediaElement` with times in seconds of the score's timeline. It is an `EventTarget` with `currentTime` (settable, seeks), `duration` (`NaN` until known), `paused`, `ended`, `playbackRate`, `defaultPlaybackRate`, `error`, `play()` (a promise) and `pause()`, and it fires the media events the player re-dispatches (DL-005) plus `canplay`. An `HTMLAudioElement` is a `SegnoMedia`.
- **`player.media`**: setting it makes the player use that object for everything it did with its internal `<audio>`. Every use goes through one private accessor. Setting `null` returns to the internal `<audio>`, which stays the default. The getter returns the external media, or `null` while the internal `<audio>` is in use.
- While an external media is set, the `audio` attribute is ignored. The internal `<audio>` keeps the source it had, paused, so the host can fall back to it at once. A change to `audio` made in the meantime applies when `media` is cleared.
- **Swapping while playing keeps the place.** The player detaches every listener from the old media first, reads its `currentTime` and whether it was playing, and pauses it. It then gives the new media that `currentTime` and the player's rate (`defaultPlaybackRate` and `playbackRate`, within what the new media can play, DL-038), and plays it if the old one was playing. The markers and the built-in controls update at once. The host uses this to start on the MP3 and switch to its synthesizer when that is ready, and back if the synthesizer fails.
- **Readiness.** A media counts as ready when it fires `canplay`, or at once if its `duration` is already known when it is set. The player's own `canplay` fires once per media, as it does once per `audio` source, when the media is ready and the sync map has settled (DL-017). The audio-length check (DL-017) uses the current media's duration and runs again on each swap.
- **A failing media.** A media is often swapped out because it failed, so errors reading or pausing the old one are ignored, and a time or rate that isn't a finite number becomes 0 and 1. An error from the new media is thrown from the setter, after the markers and controls show the new state. A swap doesn't announce the bar to screen readers.
- **Removing the player** pauses its media, as before, and stops listening to a host's media, which may outlive the element. Putting the player back listens again. A `media` (or `sync`) set before the element was defined is taken over when it connects.
- **The loop** (DL-017) is unchanged and reads the current media's `currentTime` every animation frame while playing, so the markers don't depend on how often a media fires `timeupdate`. The leads still scale with the rate.
- **User gestures.** The built-in controls, the keyboard shortcuts and clicks on bars call the media's `play()` synchronously within the event handler, so a host's synthesizer can resume its `AudioContext` inside the gesture.
- **Errors.** The media's `error` event is re-dispatched as before, and the player's `error` property reads the current media's error. The host decides what to do, for example setting `media = null`.

## Rationale

- An object with the media element's shape is the smallest contract that lets a host bring any engine, a synthesizer or another kind of player, without Segno carrying one. The player stays within its size budget and DL-001's scope.
- Following `HTMLMediaElement` means the internal `<audio>` and an external media are used the same way, and an external media can be tested against the same expectations.
- Keeping the internal `<audio>` loaded makes falling back instant, and keeping the place on a swap makes switching engines inaudible apart from the sound itself.
- Reading `currentTime` per frame was already how the loop worked. It is what makes a host's coarse `timeupdate` harmless.

## Consequences

- A host's media must keep the score's own timeline: if its times differ from the sync map's, the markers are wrong, and the player can't tell.
- Events the old media fires during a swap (its `pause`) are not re-dispatched. The new media's own events are, including its `play`.
- The roadmap's open question gets one answer for tempo: a synthesizer can live in the host. Transposition remains open, since transposed sound would still disagree with the fixed pages.
