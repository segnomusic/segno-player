## Context

The built-in controls, page descriptions, canvas label and polite current-bar announcements currently contain English strings. Changing language must not rebuild the player or disturb an active practice session.

## Decision

Use the catalog selected by DL-028 for all built-in control text, score-mode options, control and score ARIA labels, seek value descriptions, page and canvas descriptions, and current-bar announcements. Update existing text and attributes in place rather than recreating buttons, inputs, options, page images or the canvas. Preserve playback state, current time, rate, follow state, mode selection, settings-panel expansion, focus and slotted custom controls. Language changes must not reload score or audio assets or redraw the canvas.

Translate an existing polite bar announcement in place when language changes, but do not start continuous bar announcements during playback. Subsequent pause and seek announcements use the new language. Custom slotted controls and externally supplied score titles remain owned by the embedding site.

Document `lang` usage and fallback behavior, add a minor Changeset for the additive feature, and test English and Swedish controls including screen-reader text and live switching during playback. Leave changes local and unpushed until the maintainer completes local end-to-end testing.

## Rationale

Keeping the existing DOM nodes and media lifecycle avoids lost keyboard focus, closed settings, duplicate listeners and interrupted audio. Accessibility strings are as much part of localization as visible labels.

## Consequences

The controls need an internal text-update entry point, not a new public locale API. Existing CSS parts, event contracts and the full-score/canvas behavior remain unchanged.
