## Context

The upcoming Fria Noter integration needs a Swedish player, while existing integrations use English. The string inventory is small enough for built-in dictionaries rather than a translation framework.

## Decision

Store player-owned user-facing messages in one typed dictionary map with complete `en` and `sv` entries. Both entries satisfy a shared schema, including the score-mode names. Messages containing page numbers, bar numbers, times or an optional score title are whole-phrase formatter functions, not concatenated translated fragments. Keep the catalog internal to the player package and add no runtime dependencies.

Translate visible controls and accessibility text. Keep developer-facing exceptions and console diagnostics in English, keep supplied score titles unchanged, and leave the core and sync-map format untouched. Retain the existing clock-style time display; tempo percentages may use the catalog to express language-specific spacing. Do not add runtime dictionary registration, lazy language packs or a language picker.

## Rationale

A typed catalog makes missing translations a compile-time error and allows natural word order without introducing an i18n framework. Bundling two small dictionaries keeps CDN use and server-side importing as simple as before.

## Consequences

Tests cover both complete catalogs and parameterized phrases, and future languages must satisfy the same schema. The implementation stays within the existing player size budget.
