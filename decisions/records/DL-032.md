## Context

The scoped package name already says player, making the component import `@segnomusic/player/player` redundant. Fria Noter is the only known consumer and the maintainer explicitly prefers a clean pre-1.0 break over preserving the old path.

## Decision

For 0.3.0, expose the existing component module at the package root `@segnomusic/player`. Remove the `./player` export entirely, without a compatibility alias. Keep `@segnomusic/player/core` and `@segnomusic/player/package.json` unchanged. Point root JavaScript and TypeScript resolution directly to `dist/player/index.js` and `dist/player/index.d.ts`; do not add a wrapper or move files. Preserve the existing sideEffects declaration, browser registration behavior, lazy import support and SSR-safe import behavior. The explicit CDN file URL remains unchanged.

Use a minor Changeset to target 0.3.0 from 0.2.x. Mark removal of the old subpath as breaking and show migration for side-effect imports, dynamic imports and named/type imports in the release notes and README. Historical decisions and released changelog entries retain their original paths. Do not change the Fria Noter repository as part of this package change.

## Rationale

The package root is a natural entry point for the primary product. A separate core subpath still keeps build-time consumers DOM-free. Directly reusing the same module avoids extra loading, duplicated registration, and wrapper-specific tree-shaking behavior. Before version 1.0, a minor release clearly communicates the requested breaking change.

## Consequences

- Amends the export layout in DL-010, DL-018 and DL-025, not their ESM, package identity or registration decisions.
- Consumers must replace the old component path with the package root, including type-only and lazy imports.
- Packed-package smoke tests validate root imports, declarations, browser registration and rejection of the removed subpath, while retaining core and SSR checks.
- Version/changelog/lockfile updates and publication continue through the existing release PR workflow.
