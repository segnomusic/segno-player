## Context

DL-001 puts a small CLI in scope, to build sync maps at build time. DL-010 planned it as a `segno` bin in the one package, so the core, the player and the CLI change and are tested together, and DL-025 kept the name `segno` after the package became `@segnomusic/player`. DL-026 then deferred "the unscoped `segno` CLI" to a separate repository, as one line of its consequences. The roadmap lists `segno build-sync` as a step toward 1.0.

The commands planned so far work on the player's own inputs and are thin layers over the core. Their main risk is drifting from the sync map format (DL-003) and from what the player accepts.

## Decision

The CLI lives in this repository and ships in `@segnomusic/player` as the bin `segno` (`"bin": { "segno": "./dist/cli/index.js" }`). It holds commands that prepare the player's inputs; each command beyond `build-sync` gets its own decision.

- The sources are in `src/cli` and compile with `tsc` to `dist/cli`, through their own build config that adds Node's types. The CLI is the only part of the package that uses Node APIs. It uses the core only through `src/core/index.ts`, and never the player.
- `dist/cli` is not a subpath export and not a library: nothing imports it, so it adds nothing to `sideEffects` or to the browser size budgets.
- The package has a single bin, so `npx @segnomusic/player <command>` runs it without an install, and `segno <command>` works in the npm scripts of a project that depends on the package.
- No runtime dependencies: arguments are parsed with `node:util` `parseArgs` and files read with `node:fs/promises`. It runs on the package's Node version (22+).
- `segno --help` (`-h`), `segno --version` (`-v`) and `segno <command> --help` print to stdout and exit 0. No command, or an unknown one, prints the usage to stderr and exits 2. Wrong arguments to a command print the problem and a pointer to that command's `--help` to stderr, and exit 2.
- The CLI is tested with Vitest in Node, in its own `cli` project, by calling its entry function with arguments and capturing its output and exit code. The packed-tarball check (DL-026) also runs the installed bin.

An unscoped `segno` package that only depends on `@segnomusic/player` and exposes the same bin remains possible later, for a shorter `npx segno`. It is not published now.

## Rationale

- One package keeps DL-010's reasons: one install and one version, and the CLI is tested against the same core and format version it ships with. A separate repository would add a release, a CI setup and a version-compatibility matrix for about a hundred lines of code.
- Building on the public core entry keeps the CLI an ordinary consumer of the core, the same as a site's own build script, so the core stays DOM-free and Node-free (DL-004).
- A single bin is what lets `npx` run a scoped package's command without `-p`.
- A wrapper package can be added at any time without changing this one, so the shorter name is not given up.

## Consequences

- This replaces DL-026's line deferring the CLI to a separate repository; DL-026's release model is otherwise unchanged.
- `package.json` gains `bin`, `files` gains `src/cli`, and the build gains a third `tsc` step for `src/cli` (`tsconfig.build.cli.json`, without declarations). The entry file starts with `#!/usr/bin/env node`, so the SPDX check accepts the header on the line after a shebang.
- The SPDX check, Biome, the type check and the coverage floor (DL-011) cover `src/cli` like the rest of `src`.
- Commands that are not about the player's inputs (for example a hosted converter's client) do not belong here.
