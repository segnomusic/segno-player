## Context

The project moved from `jimutt/segno` to `segnomusic/segno-player`, and its GitHub Pages site moved with it. The `segnomusic` npm scope is reserved for this and possible future Segno Music tools. The package has not been published yet, so its public name can still change without a migration for consumers.

## Decision

Use **Segno / Segno Music** as the overall brand, **`segnomusic/segno-player`** as this repository, and **`@segnomusic/player`** as the single npm package. Its existing subpaths become `@segnomusic/player/core` and `@segnomusic/player/player`; the CLI remains named `segno` when added.

The demo root is `https://segnomusic.github.io/segno-player/`, with pull request previews at `https://segnomusic.github.io/segno-player/pr-preview/pr-<number>/`. Repository metadata, documentation, demo links, package imports and CDN examples, contributor commands, and SPDX source links use the new locations and package name. GitHub Pages continues to deploy from `gh-pages` as before.

## Rationale

A shared organization and npm scope leave room for related tools without making this repository or package ambiguous. Renaming before the first npm release avoids legacy package aliases and installation migrations. Repository-relative implementation details and the existing Pages deployment model do not need to change.

## Consequences

- The package name, lockfile root, smoke-test imports, and publishing metadata must stay in sync.
- The old demo URL is no longer valid; active documentation must not point to it.
- Older decision records retain their historical names and URLs; this decision amends those details rather than rewriting their history.
